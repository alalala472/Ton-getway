# Ton/Guftro AI Gateway

Mobile-first AI API Gateway for Vercel. The gateway generates `sk-tx-...` client keys and stores provider API credentials encrypted at rest.

## Stack
- Next.js 16 + TypeScript
- PostgreSQL + Prisma
- Vercel Node.js Functions
- Provider adapters: OpenAI-compatible, Anthropic, Gemini, OpenRouter, Ollama, Custom

## Important architecture
`sk-tx-...` is a gateway credential generated by this application. It is not a provider key. The provider key remains server-side and encrypted.

Each gateway key maps to one API configuration/provider.

## Environment
Copy `.env.example` to `.env` and set:
- `DATABASE_URL`
- `SESSION_SECRET`
- `ENCRYPTION_KEY` (64 hex characters; generate with `openssl rand -hex 32`)
- `ADMIN_USERNAME`
- `ADMIN_PASSWORD`

Do not expose provider keys or gateway keys through `NEXT_PUBLIC_*` variables.

## Local
```bash
npm install
npm run db:push
npm run db:seed
npm run dev
```

## Vercel
1. Push this folder to GitHub.
2. Import the repository into Vercel.
3. Create a PostgreSQL database (Neon is a suitable Vercel-oriented option) and put its connection string into `DATABASE_URL`.
4. Add `SESSION_SECRET`, `ENCRYPTION_KEY`, `ADMIN_USERNAME`, and `ADMIN_PASSWORD` as Vercel environment variables.
5. Deploy.
6. Run `npm run db:push` against the production database or use a migration workflow before first production use.

## Gateway usage
Base URL:
`https://YOUR-DOMAIN/v1`

API key:
`sk-tx-...`

Primary endpoint:
`POST /v1/chat/completions`

Model discovery:
`GET /v1/models`

Example headers:
```http
Authorization: Bearer sk-tx-...
Content-Type: application/json
```

## Provider base URLs
- Gemini default: `https://generativelanguage.googleapis.com/v1beta`
- OpenAI-compatible: provider's compatible API base URL
- Anthropic: `https://api.anthropic.com/v1`
- OpenRouter: `https://openrouter.ai/api/v1`
- Ollama: your reachable Ollama URL, e.g. `https://your-host.example/api`
- Custom: provider-specific URL/format

Do not assume a local `localhost` Ollama URL is reachable from Vercel; use a reachable remote Ollama endpoint.

## Production notes
- The current V1 keeps request logs metadata-only by default.
- Body logging should be enabled deliberately because prompts/responses can contain sensitive data.
- Proxy pool inventory is included; connect only to proxies you are authorized to use. Do not use proxy rotation to bypass provider rate limits or access controls.
- Quota is reported as provider data becomes available; `UNKNOWN` is used when a provider does not expose quota data.
- Provider adapters should be extended as provider APIs evolve. Gemini's current official API has multiple primitives, including Interactions, while standard `generateContent` remains documented; this gateway keeps a focused chat adapter for V1.

## Current adapter behavior
The public `/v1/chat/completions` surface is normalized to an OpenAI-style response for Gemini, Anthropic, and Ollama where the adapter can map the provider response. OpenAI-compatible/OpenRouter/custom providers are passed through. Provider-specific advanced features should be added deliberately rather than silently dropped.

Gemini currently supports native model discovery and streaming through its documented REST endpoints. Provider APIs change over time, so keep adapters versioned and test them when providers change their APIs.
